# AI 可读性设计：让人的注意力用在关键问题上

上一期讨论了 DeepSeek SuperAgent 的注意力原则：尽可能减少人类注意力消耗，提高 AI 工作的实际价值。

随着 Agent 能够独立完成越来越多的任务，人仍然需要理解工作过程、检查结果并纠正错误。当监督成本随着 AI 工作量一起增长，人的注意力就会成为自动化规模的限制因素。

**如何通过可读性设计，降低人类理解、监督和纠错 AI 工作的成本？**

## 为什么 AI 的行为难以解释？

机器学习领域有一项研究方向，称为**机制可解释性（Mechanistic Interpretability）**。

传统程序的执行过程通常可以沿着代码追踪。大模型的能力则来自训练形成的大量参数和计算结构。研究者需要通过实验识别内部特征及其相互作用，才能解释特定行为是怎样产生的。

对于 Agent 工程，另一个层面的问题更加直接：即使尚不能完整解释模型的内部计算，我们仍然可以通过工作记录、状态管理和验证证据，让外部执行过程变得更加清晰。

我们希望使用者能够迅速理解：AI 正在做什么，依据什么执行，完成了哪些工作，结果有没有经过验证，出现错误应该检查哪里。

## 从 Team Skill 的迭代看可读性设计

[Team Skill](<https://github.com/Ri0n72Y/agent-identity>) 的迭代提供了几个实际案例。

**精简任务请求，减少重复信息**

在之前的实践中，Agent 之间的 Request 越来越长，重复记录了 Issue、PR 中已有的任务要求与历史决策。Team交接issue的设计本来就是为了减少交接时信息携带，但AI本着写的多就一定不会缺的原则，把能写的都写了进去，导致交接的信息压缩目的完全失效。

将任务请求收敛为简短指令和权威资料链接。接收者根据链接读取必要内容，避免多个位置维护重复的信息。但在Skill中尽管做出了相当严格的强调，gpt仍然会在几轮对话后忘记，需要反复强调。感觉繁杂的汇报已经写进了gpt的脑回路里，就像那个经典的“不是-而是”的诡异关联一样。

可读性最终服务于工作正确性，核心是让Agent的工作不要偏离预期。让人以更少的注意力掌握关键状态，并在必要时获得足够的证据，才能支撑更大规模的 Agent 协作。

Team Message的方案实际上恢复了Superagent设计中的Mailbox设定。在这个基础上增加了可审计的result，算是agent的“劳动记录”。基于这个统计其劳动成果的上下文关系。增加一条可统计的链路。

## 实践分享：从工具使用到 AI 权限与执行规范

本周Bruce分享了使用 DSH 与飞书 CLI 完成报销工作的经历。这次实践的价值，在于随着任务推进，逐渐认识了 AI 的权限、授权与执行流程之间的关系。

### 从使用工具到理解权限

最初使用现成工具，通过飞书企业自建应用的机器人身份调用 API。实际使用中发现，机器人能访问的资源和能够执行的操作都受到限制。

后来改用飞书官方 CLI，通过 OAuth 获取用户授权，使用用户身份访问飞书资源，解决了部分操作限制。

这个过程中逐渐认识到：**权限在很大程度上决定了 AI 能做什么。**

同样的模型，获得不同的身份和授权，能够执行的工作就会发生变化。用户授权又涉及应用权限、资源访问范围和具体操作的执行边界。

### 结果正确 ≠ 流程正确

在报销自动化中，又遇到了另一个问题。

Agent 能够正确核对订单、整理数据并写入记录，却选择了直接修改数据表的方式，绕过了原本的表单提交流程。

**数据结果正确，但业务要求的提交来源与操作记录缺失了。**

这实际上暴露了一个容易被忽视的问题：流程规范本身也是被要求交付的成果之一。

对于 AI 来说，如果没有明确要求，它可能会选择最直接的执行路径来完成任务。但在实际的组织生产中，身份、来源、审批和操作记录都可能是工作成果的一部分。

通过这次错误，我们进一步认识了授权与执行之间的关系：**拥有操作权限，不代表可以采用任意方式完成工作。**

### 从授权到执行规范

随着 AI 获得更多权限，需要进一步明确哪些操作可以自动执行，哪些需要人工确认，哪些禁止委托。

实践中逐渐形成了三类约束：读取和整理可以自动执行；修改文档、上传文件等操作需要确认；发送消息和提交审批由本人操作。

同时，执行后的回读检查也成为必要步骤。此前清理旧数据时曾遗漏部分记录，直到回读才发现并修正。

这次实践逐渐从使用现成工具，发展到认识权限与授权，再到明确执行过程需要遵守的业务规范。

**Agent 的能力由工具与权限共同决定，而工作的正确性还需要包含执行过程本身。**

## 小技巧：去除常见AI味

本周分享了一条日常使用的文字优化提示词：

> 去掉无意义的假口语化、比喻、总结，改掉不是而是句式，使用中文习惯的主谓宾表达方式。去掉内容的重复、防御性表述。去掉无意义的历史信息。

以本周的飞书自动化实践为例。

**原文：**

> 问题出在身份上。机器人是个「外人」——它说的话显示为机器人说的，不是我说的话；它想主动私聊我，得先等我先跟它说话才有会话 ID；它想读写某个文档，还得我把文档分享给它。

**修改后：**

> 最初使用飞书企业自建应用，通过机器人身份调用 API。消息以机器人身份显示，主动私聊受到会话 ID 限制，访问部分文档还需要额外授权。

修改保留了身份、接口限制和授权问题，删除了比喻和重复解释。

这类优化主要针对表达形式。事实、操作过程、具体数据和技术结论仍然需要独立检查。
